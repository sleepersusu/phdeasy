教授研究檔案流水線

已確認 · 2026-10-25 追加多平台、全文找尋鏈、Zotero

輸入一位教授，產出近五年（2022–2026 出版）所有文章的合作網絡、主要合作者、研究領域、研究計畫，以及每篇文章的解析卡。每個說法都追溯到原文頁碼。

實測教授：Fukuoka, Yoshimi（機構於停 1 確認）

流程

停 1　確認身分與文章stop1

你給姓名與學校。腳本從 OpenAlex 找身分、列文章、去重，再用 ORCID、PubMed、Europe PMC、Semantic Scholar、arXiv 交叉比對漏收文章。全文找尋鏈逐篇找免費全文並歸位到 pdfs/。你確認人與文章，真的找不到的再補進 inbox/。

以下全自動
標準化ingest

雜湊原檔，PDF 轉成帶頁碼標記的文字，對應到文章 id。讀不出來的當場記例外。

合作與領域network

腳本用作者 id 計算合作者排名、年度、機構、作者序與主題分佈。Haiku 另外獨立數前 10 名。

研究計畫grants

查 NIH RePORTER、NSF、GRB、CORDIS、UKRI，加上論文致謝段的計畫編號。姓名與機構都吻合才收。

解析卡cards

Opus 寫卡，Sonnet 另外獨立抽設計與樣本；腳本比對，不一致交給裁決者。推翻者攻擊缺口、貢獻、發現、限制。腳本逐句核對引句。

總覽profile

腳本彙整數字，agent 寫領域敘述並附卡片 id，推翻者檢查。產出 profile.md 與網頁。

獨立驗收verify

沒參與過的 agent 只看判準與產出逐條判定。E2E 腳本重跑所有核對。

停 2　一次呈現stop2

依序呈現：例外與熔斷、驗收逐條結果、各段數字、花費、產出位置、需要你決定的事。

全文找尋鏈

每篇依序嘗試，找到就停。每個網址最多重試 3 次，每次嘗試都記錄。下載內容要通過檔頭檢查，付費牆網頁不算數。全部失敗才標「無免費全文」並列出試過的來源。

  1. 你的 Zotero 文獻庫（唯讀，複製不移動）
  2. OpenAlex 所有開放位置
  3. Unpaywall（需要你提供 email）
  4. Europe PMC：PDF 與全文 XML
  5. PMC 開放取用服務
  6. Semantic Scholar
  7. 預印本：arXiv、bioRxiv、medRxiv、Research Square、JMIR Preprints
  8. CORE（需要 API key）
  9. 你補進 inbox/ 的 PDF

產出整理

位置內容
pdfs/<年>/全文歸位，檔名為文章 id、第一作者、短標題；index.csv 記錄每篇的狀態與來源
out/profile.md教授總覽：合作者、領域、計畫，另發布成網頁
out/papers/每篇一份解析卡
out/data/works、coauthors、topics、grants 四張 CSV
out/zotero/RIS 檔，含 PDF 附件、解析卡筆記、標籤，由你匯入 Zotero
work/中間產物，不給人讀

每篇文章解析卡的欄位與監督

欄位內容監督方式
大意3–5 句引句核對
研究設計類型、方法、分析雙軌 Opus ∥ Sonnet → 裁決
研究樣本對象、n、地點、期間、抽樣雙軌 數字必須出現在引句中
研究缺口作者主張的缺口引句核對 ＋ 推翻者
解決什麼研究問題與貢獻引句核對 ＋ 推翻者
發現主要結果與數字引句核對 ＋ 推翻者 ＋ 數字比對
研究限制分「作者自述」與「推論」自述需引句；推論需標明並經推翻者

引句格式固定為 "原文照抄" [W1234567, p.5]。來源沒寫就寫「來源未提及」。

教授層級的欄位

欄位監督方式
書目（標題、年、期刊、DOI、作者序）OpenAlex 與 Crossref 機械比對
合作者排名腳本以作者 id 計算，Haiku 獨立數前 10，兩者需一致
研究領域分佈由腳本算；敘述每句附卡片 id，推翻者檢查
研究計畫出處快照或致謝引句，腳本確認編號出現在出處；推翻者查是否同一人

驗收判準

  1. 每篇有 OpenAlex id，出版年 2022–2026，無重複
  2. 停 1 確認的每篇文章都有一張卡
  3. 每張卡 7 欄齊全，空的寫「來源未提及」
  4. 全文卡引句核對 100% 通過；僅摘要卡標 abstract_only
  5. 雙軌每個不一致都有裁決或標 unresolved
  6. 合作者前 10 名：腳本重算一致，且與 Haiku 計數一致
  7. 每個研究計畫都有出處，編號出現在出處中
  8. 總覽每個主張都追溯到卡片 id 或書目
  9. inbox/ 與 raw/ 原檔雜湊不變
  10. state.json 與實際產出一致

熔斷

  • 例外篇數超過 30%
  • 文章超過 80 篇（停 1 先問）
  • subagent 總 token 超過每篇 150k × 篇數 × 1.5

判斷規則

  • 摘要與內文衝突時以內文為準
  • 預印本與正式版只留正式版
  • 社論、勘誤做短卡
  • 自動段不增刪文章
  • 判不出來就標 unresolved，不硬判

常見錯誤由哪一層擋住

錯誤擋住的那一層
同名同姓抓錯人停 1 本人確認；計畫另有推翻者
捏造引句或頁碼引句核對腳本逐字比對該頁
樣本數抄錯雙軌比對，數字必須在引句中
把背景文獻的發現當成本文發現推翻者
研究限制腦補自述與推論分開標
合作者同人不同寫法用作者 id 計數，不用姓名字串
論文裡藏的指令所有工作說明都寫明不執行
中斷後重做state.json 與逐篇完成標記

實測結果：Fukuoka, Yoshimi

項目結果
文章28 篇；OpenAlex 漏收的 2 篇由 PubMed／Europe PMC 補回
免費全文22/25；3 篇只有摘要
合作者77 位，獨立計數 36/36 一致；3 組可能同一人待你決定
研究計畫本人主持 5、致謝 14、合作者主持 9、待確認 2；推翻 10
解析卡28/28，引句 1,274 則全數核對通過；雙軌不一致 23 筆全數裁決；推翻 440 條中 7 條
總覽60 句出處 60/60，推翻 2
E2E 與驗收E2E 14/14；獨立驗收第 1 輪 10/12 → 修一輪 → 第 2 輪 11/12，剩餘一項已修正
花費47 個 subagent，約 4.68M tokens（上限 5.63M）

實測中修掉 18 個問題，例如：附錄被當成正文、PMC 全文因伺服器錯誤被判為沒有、OpenAlex 把同一人拆成兩個 id、引句在參考文獻括號中間切斷。每個都先寫會失敗的測試再修，目前共 203 個測試。

作者界線

解析卡與總覽由 agent 寫，作為閱讀素材。「這位教授適不適合我」的判斷、寄給教授的信、研究計畫書由你自己寫。agent 只提供素材，例如可以問教授的問題清單。
